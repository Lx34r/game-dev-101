# 七日配色基础：从色相环到游戏 UI 的可读配色

<ArticleTags />

配色不是“选几个好看的颜色”。它同时在处理三件事：**信息层级、情绪氛围、可读性**。游戏里还要多一层：玩家在高速移动、特效堆叠、不同显示器与色觉条件下，仍然要能分清敌我、稀有度与危险提示。

这篇笔记按《七日掌握设计配色基础》的课程结构，把色彩基础重新组织成一条可执行的路径：先看明度，再做色相，再谈心理，最后落到游戏 UI 与验收。

## 1. 第一天：先看明度，不要先挑颜色

把画面转成灰度，如果层级仍然清楚，配色大概率成立；如果灰度下糊成一片，再漂亮的色相也救不了。

观察练习：

- 收集 10–20 张你喜欢的游戏截图、海报或界面；
- 转灰度，看主体、背景、强调是否仍然分层；
- 提取每张图的 5 个主要颜色，记录它们的明度关系；
- 不看色相，只问：谁最亮、谁最暗、谁的面积最大？

这一步的目标不是找到“标准答案”，而是建立对明度结构的敏感度。

## 2. 第二天：色彩三属性与色调

任何颜色都可以拆成三个维度：

| 属性 | 含义 | 游戏中的用途 |
| - | - | - |
| 色相 Hue | 红/黄/蓝等颜色种类 | 阵营、元素、情绪方向 |
| 明度 Value | 明暗程度 | 层级、可读性、空间感 |
| 饱和度 Saturation | 鲜艳/灰浊程度 | 强调、材质、风格 |

“色调”是明度与饱和度的组合印象：浅色调、暗色调、鲜艳色调、灰浊色调。游戏 UI 常用**低饱和背景 + 高饱和强调**，因为背景要退后，信息要跳出。

一个常见错误是全场高饱和：每个按钮、图标、特效都在抢注意力，结果没有重点。把饱和度当预算分配，而不是平均撒满。

## 3. 第三天：色相环与六种基本配色

| 类型 | 关系 | 适合 | 风险 |
| - | - | - | - |
| 单色 | 同一色相，变化明度/饱和度 | 统一、克制 | 容易单调 |
| 类似色 | 色相环相邻 30° 左右 | 和谐、氛围 | 对比不足 |
| 互补色 | 色相环相对 180° | 强对比、强调 | 面积失衡会刺眼 |
| 分裂互补 | 互补色两侧 | 对比但更柔和 | 颜色数量变多 |
| 三角配色 | 色相环三等分 | 活泼、丰富 | 难统一 |
| 四角配色 | 两组互补 | 复杂、节庆感 | 容易花 |

游戏 UI 更常用“类似色 + 一个互补强调”而不是完整三角配色。背景、面板、文字保持低对比的类似关系，关键按钮/掉落/危险用一个高对比色跳出。

## 4. 第四天：对比、面积与位置

对比不只来自色相。明度对比、饱和度对比、冷暖对比、面积对比都会影响可读性。

### 60-30-10 不是硬规则，但是好起点

- 60%：主导色/背景；
- 30%：次级色/面板与结构；
- 10%：强调色/交互与关键信息。

在游戏 HUD 里，背景与常驻信息应该占大部分面积，强调色只留给“现在需要行动”的东西。

### 同时对比

同一颜色放在不同背景上，看起来会不同。灰色在红底上偏绿，在蓝底上偏黄。UI 验收要在真实背景上检查，而不是只看色板。

### 面积与位置

高饱和颜色面积越大，压迫感越强；放在边缘与放在中心，视觉权重也不同。想强调一个按钮，不一定要更亮，也可以让它周围更暗、更空。

## 5. 第五天：色彩心理与题材

色彩会触发联想，但联想高度依赖文化、题材与个人经验。不要把“红=危险、蓝=冷静”当成绝对规律。

可用的方向：

- **冷暖**：暖色更靠近、活跃；冷色更后退、克制；
- **明度**：高明度轻、低明度重；
- **饱和度**：高饱和更刺激，低饱和更沉稳；
- **文化**：同一颜色在不同地区含义不同，发行前要本地化检查。

游戏题材会决定主色：废土常用低饱和黄褐与灰绿，科幻常用冷蓝与青色高光，肉鸽/刷宝常用高对比强调色标记掉落与稀有度。关键是让色彩服务于世界观与可读性，而不是套模板。

## 6. 第六天：游戏 UI、HUD 与场景

### 语义色要固定

一旦定义，就保持一致：

- 危险/受击：红或橙；
- 治疗/增益：绿或青；
- 稀有/奖励：金或紫；
- 信息/魔法：蓝；
- 禁用/不可用：灰。

但不要只靠颜色。色觉障碍玩家可能分不清红绿，必须叠加图标、形状、纹理或文字。

### 可读性优先于“氛围”

- 战斗中的伤害数字、预警圈、精英标记需要最高对比；
- 背景特效不能盖住 HUD；
- 低血量、技能冷却、可交互对象要有独立通道；
- 场景色调可以统一，但交互物必须从环境中跳出。

### 一个可用的暗色 UI 色板

| 角色 | 色值 | 用途 |
| - | - | - |
| 背景 | `#0B0F14` | 主背景，占大面积 |
| 面板 | `#151B23` | 卡片、弹窗 |
| 主文字 | `#E6EDF3` | 高对比正文 |
| 次文字 | `#9AA4B2` | 辅助信息 |
| 强调 | `#F5C451` | 奖励、关键交互 |
| 危险 | `#E5484D` | 受击、危险提示 |
| 成功 | `#46A758` | 治疗、完成 |
| 信息 | `#4C8DFF` | 魔法、链接、提示 |

强调色只占约 10% 面积；危险/成功/信息色尽量配图标或形状，避免只靠色相区分。

## 7. 第七天：对比度与验收

### 对比度公式

先算相对亮度：

$$
L = 0.2126R + 0.7152G + 0.0722B
$$

对比度：

$$
\text{Contrast} = \frac{L_{light} + 0.05}{L_{dark} + 0.05}
$$

正文建议至少 4.5:1，大字号至少 3:1。游戏 UI 的伤害数字、关键按钮应高于最低标准。

```csharp
static float Linear(float c) =>
    c <= 0.04045f ? c / 12.92f : Mathf.Pow((c + 0.055f) / 1.055f, 2.4f);

static float Luminance(Color c) =>
    0.2126f * Linear(c.r) + 0.7152f * Linear(c.g) + 0.0722f * Linear(c.b);

static float Contrast(Color a, Color b)
{
    float la = Luminance(a), lb = Luminance(b);
    float hi = Mathf.Max(la, lb), lo = Mathf.Min(la, lb);
    return (hi + 0.05f) / (lo + 0.05f);
}
```

### 验收流程

1. **灰度检查**：层级是否还成立；
2. **对比度检查**：正文、按钮、伤害数字是否达标；
3. **色觉模拟**：红绿/蓝黄模拟下能否区分敌我与稀有度；
4. **真实背景检查**：在战斗特效、场景光照下看 UI；
5. **多显示器检查**：不同色域/亮度下是否仍可读；
6. **一致性检查**：同类信息是否使用同一语义色。

## 8. 七天练习表

| 天 | 练习 | 产出 |
| - | - | - |
| 1 | 收集并灰度分析 10 张参考 | 明度层级笔记 |
| 2 | 拆解三属性与色调 | 3 套背景/强调色 |
| 3 | 用色相环做 6 种配色 | 6 个 UI 色板 |
| 4 | 调整对比与面积 | 60-30-10 版式 |
| 5 | 做题材/情绪版本 | 2 套氛围方案 |
| 6 | 落到 HUD/按钮/稀有度 | 可交互原型 |
| 7 | 灰度、对比度、色觉验收 | 修正后的最终色板 |

## 9. 检查清单

- 灰度下层级是否清楚？
- 背景、面板、文字是否保持低饱和/低对比？
- 强调色是否只占小面积？
- 语义色是否一致，且不只靠颜色区分？
- 正文与关键信息的对比度是否达标？
- 色觉模拟下敌我/稀有度是否仍可辨？
- 场景光照与特效是否盖住 HUD？
- 是否有可复用的色板与命名，而不是散落硬编码？

配色的终点不是“看起来高级”，而是让玩家在正确的时间看到正确的信息，并感到这个世界的气质一致。先解决明度与对比，再谈色相与情绪，最后用数据与真实场景验收。
