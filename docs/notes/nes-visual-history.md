# 红白机视觉史：硬件预算如何塑造像素美学

<ArticleTags />

红白机的画面今天看仍然有辨识度，但它并不是“故意做得粗糙”。256×240 的分辨率、受限的调色板、每行最多 8 个精灵、两个命名表——这些硬性预算共同决定了开发者能画什么、不能画什么。

Bitmap Books 的《NES/Famicom: a visual compendium》用大量游戏截图与开发者访谈记录了这段视觉史。这篇笔记不复述图鉴，而是把硬件约束、视觉技巧与今天的像素游戏设计连起来。

## 1. 一台 8 位机的视觉预算

| 项目 | NES/Famicom 限制 | 视觉后果 |
| - | - | - |
| 分辨率 | 256×240（NTSC） | 画面天然偏向大色块与清晰轮廓 |
| 背景 Tile | 8×8 像素，约 32×30 格 | 960 个背景格组成一屏，重复是常态 |
| 背景调色板 | 4 组，每组 3 色 + 1 个共用背景色 | 同一场景的颜色必须精打细算 |
| 精灵调色板 | 4 组，每组 3 色 + 透明 | 角色/敌人共享有限的颜色预算 |
| 精灵数量 | 64 个，每扫描线最多 8 个 | 同屏敌人多时会闪烁、需要 multiplexing |
| 命名表 | 2KB VRAM，两张命名表 | 滚动、分屏与状态栏需要技巧 |
| 图形 ROM | CHR ROM，可配合 Mapper 切换 | 后期卡带能突破部分限制 |

这些数字解释了一个现象：红白机的画面不是“低分辨率版的写实”，而是**在极小预算下做视觉编码**。

## 2. Tile：视觉的原子单位

NES 的背景由 8×8 的 Tile 拼成。一个屏幕 32×30 格，意味着美术必须先设计一套可复用的“视觉字母表”：

- 地面、墙面、草地、砖块、水面；
- 转角、边缘、阴影、装饰；
- 用有限的 Tile 组合出无限的地图。

这带来两个直接结果：

1. **重复是设计的一部分**。开发者用同一组 Tile 通过排列、翻转、调色板切换制造变化。
2. **轮廓比细节重要**。8×8 里画不下复杂纹理，但可以画清一个可识别的形状。

现代像素游戏即使不受硬件限制，也常主动采用 Tile 网格：它让关卡编辑、碰撞、光照与美术资产保持同一套坐标系统。

## 3. 调色板：颜色是预算，不是列表

NES 主调色板约 54 色，但屏幕上真正可用的颜色被调色板组限制：

- 背景 4 组，每组 3 色 + 共用背景色；
- 精灵 4 组，每组 3 色 + 透明。

因此同一屏幕的“颜色预算”非常有限。开发者常用：

- **共享色**：让不同物体共用同一组颜色，减少调色板切换；
- **调色板交换**：同一套 Tile 换色成为不同敌人/阵营/环境；
- **抖动（dithering）**：用像素点阵模拟中间色；
- **黑色轮廓/留白**：在有限颜色中拉开主体与背景。

这也是为什么红白机游戏常有强烈的“图形感”：颜色不是均匀铺开的，而是按信息重要性分配的。

## 4. Sprite：数量与闪烁

NES 最多 64 个 Sprite，每条扫描线最多 8 个。超过后，多余的 Sprite 会消失或闪烁。

开发者的应对方式：

- **Sprite multiplexing**：在不同扫描线复用硬件精灵，让同屏显示更多对象；
- **优先级排序**：确保玩家、子弹、危险提示优先显示；
- **闪烁作为反馈**：受击无敌闪烁本来也是硬件/表现手段；
- **用背景 Tile 画静态物体**：减少精灵预算消耗。

对现代游戏的启示：同屏对象数量、特效层数与 UI 元素也会争抢“注意力预算”。即使硬件不限，画面仍然需要优先级。

## 5. 滚动、分屏与视觉分层

NES 的两张命名表让横向/纵向滚动成为可能。开发者还常用扫描线技巧：

- 在画面中途切换滚动寄存器，做出状态栏固定、背景滚动的效果；
- 用 Sprite 0 hit 等时序技巧触发分屏；
- 通过不同层速度制造伪视差；
- 用调色板/emphasis 位做整体色调变化。

这些技巧的共同点是：**先理解扫描线的时间结构，再设计画面**。今天的 GPU 管线不同，但“分层、分屏、视差、色调”仍然是场景美术的基本语言。

## 6. 图鉴里的视觉谱系

《NES/Famicom: a visual compendium》按游戏记录了这台机器的视觉演变。可以把它们粗略分成几类：

- **街机移植期**：固定单屏、强对比、像素级还原；
- **横版卷轴期**：以《超级马力欧兄弟》为代表，用滚动、天空/地面分层与清晰剪影建立平台游戏语法；
- **探索期**：以《塞尔达传说》《银河战士》为代表，用 Tile 组合、区域色调与地图结构制造世界感；
- **角色驱动期**：以《洛克人》《恶魔城》《星之卡比》等为代表，用轮廓、配色与动画帧建立角色辨识度。

这些作品的共同点不是“像素风”，而是**在固定预算内建立可读的视觉系统**：玩家一眼能分清平台、危险、敌人、奖励与出口。

## 7. 对现代像素游戏的启发

### 7.1 先做灰度与剪影

把角色/敌人做成纯黑剪影，如果仍然能区分，说明轮廓成立。红白机角色之所以耐看，很大程度是因为剪影清晰。

### 7.2 调色板先于细节

先定 8–16 个核心颜色与 3–4 个语义色（危险、奖励、治疗、信息），再画细节。颜色数量少，反而更容易统一风格。

### 7.3 Tile 与 Sprite 预算仍然有用

即使不限硬件，也可以给项目设预算：

- 一屏背景 Tile 种类上限；
- 同屏动画 Sprite 上限；
- 每个角色的调色板数量；
- 特效层数上限。

预算让美术与程序在同一张表上协商，而不是到后期才发现性能或可读性问题。

### 7.4 不要把“限制”当借口

现代显示器与引擎允许更高分辨率、更多颜色。像素游戏不必复刻 NES 的闪烁与色带；应该复刻的是**约束下的清晰决策**，而不是故意制造缺陷。

## 8. 检查清单

- 角色/敌人在灰度与剪影下是否可区分？
- 背景是否有一套可复用的 Tile 词汇表？
- 颜色是否按语义分配，而不是平均铺满？
- 同屏 Sprite/特效是否有明确优先级？
- 滚动与分屏是否保持 HUD 可读？
- 角色配色是否在不同场景光照下仍成立？
- 是否用调色板交换复用了资产，而不是复制新图？
- 是否明确了“向 8 位机致敬”与“故意低清”的边界？

红白机的视觉史说明了一件事：风格不是滤镜，而是在约束中做出的选择。理解了 Tile、调色板与 Sprite 预算，再做像素游戏时，画面会更像一套系统，而不是一张放大的贴图。
