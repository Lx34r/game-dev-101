# 独立游戏上架 Steam：从 100 美元到商店页的实务清单

<ArticleTags />

上架 Steam 不是「交 100 美元然后点发布」。它包含开发者身份、税务、AppID、商店页素材、内容问卷、审核与发布节奏几条独立的流水线，任何一条卡住都会推迟上线。

这篇笔记按实际操作顺序整理成清单。政策与费率会变化，涉及税务与合规的部分请以 Steamworks 官方文档和税务顾问为准。

## 1. 先算清楚：上架的成本不只是 100 美元

Steam Direct 的提交费用通常按「每款游戏」收取，而不是按账号一次性买断。除此之外还有隐性成本：

- 商店页素材：胶囊图、截图、预告片、文案与本地化；
- 时间：审核、修改、重新提交；
- 发行准备：愿望单积累、媒体/主播名单、Demo 与试玩节；
- 税务与收款：个人还是公司、预扣税、银行账户与地址验证。

如果目标是「第一款游戏上线」，先把这些成本写进排期，而不是只留出提交费。

## 2. 开发者注册：账号、身份、税务、收款

注册流程通常包括：

1. 创建 Steamworks 账号并完成邮箱/手机验证；
2. 填写个人或公司信息，完成身份与地址验证；
3. 填写税务问卷（如美国的 W-8BEN 系列表格）；
4. 绑定收款银行与币种；
5. 支付 Steam Direct 提交费；
6. 创建 AppID 与 Depot；
7. 配置构建上传与分支；
8. 等待账号/商店页审核。

### 税务不要凭感觉填

视频提到一个常见差异：不勾选税收协定可能按较高比例预扣，正确填写后税率可能下降。具体税率取决于个人/公司所在地区、表格类型与双边协定，必须以官方税务指引或顾问意见为准。

税务信息填错不会阻止你上传构建，但会影响后续回款；这类问题越晚发现越麻烦。

## 3. 商店页：素材与文案是审核重点

商店页通常需要：

| 项目 | 说明 |
| - | - |
| 游戏名 | 与品牌、商标、搜索词一致 |
| 简介与详细描述 | 前几句决定玩家是否继续读 |
| 标签 | 影响 Steam 推荐与相似游戏匹配 |
| 胶囊图 | 小/大/宽/竖向等多套尺寸 |
| 截图 | 真实 gameplay，不要只放概念图 |
| 预告片 | 前 5 秒给出核心玩法 |
| 系统需求 | 最低/推荐配置 |
| 内容问卷 | 暴力、成人、在线交互等 |
| AI 披露 | 生成式 AI 内容的使用说明 |
| 发行日期 | 占位日期与正式日期要分清 |

素材尺寸与规范会更新（视频提到 2024.8 起旧尺寸作废）。上传前对照 Steamworks 当前的素材规范，不要用几年前模板。

### 胶囊图的两个红线

- 文字与关键元素要留在安全区，避免被不同尺寸裁切；
- 小尺寸下仍要能读出游戏名与核心卖点，不要只在大图好看。

## 4. 审核通过 ≠ 自动上线

这是最常见的误会之一：商店页审核通过只代表页面合规，不代表游戏已经开卖。你还需要：

- 设置发行日期，或选择「即将推出」；
- 确认构建已上传到正确分支；
- 检查价格、区域定价与折扣；
- 手动点击发布（或等待预定日期自动发布）。

如果只等审核通过，可能会出现「审核过了但商店搜不到」的情况。把发布动作写进上线清单，并指定谁负责点最后一下。

## 5. 上线后的前两周

视频给了一个参考基准：头两周的评价数/表现可以分成几档，达到一定量级才算「起量」。不同品类、价格与受众差异很大，不要把它当硬指标，但可以把它作为观察窗口：

- 愿望单转化率；
- 首周评价数与好评率；
- 退款率；
- 中位数游玩时长；
- 页面访问到购买的转化。

上线前就应该准备好：
  - 商店页 A/B 素材（至少两套胶囊图）；
  - 主播/媒体名单与发送时间；
  - 首发补丁与崩溃监控；
  - 社区公告与 FAQ。

## 6. 六个常见坑

1. **税务表格填错**：回款时才发现预扣比例不对。
2. **素材尺寸过期**：胶囊图被裁切或审核退回。
3. **内容问卷漏填**：成人/暴力/在线交互项与实际不符。
4. **AI 披露遗漏**：生成式 AI 素材没有按当前口径说明。
5. **过审后没发布**：以为审核通过就自动上架。
6. **构建分支错**：商店卖的是旧版本或空 Depot。

## 7. 上线检查清单

- [ ] Steamworks 账号、身份、地址验证完成
- [ ] 税务问卷与收款账户确认
- [ ] Steam Direct 费用已支付，AppID/Depot 创建
- [ ] 构建上传到正确分支，能在干净账号下载
- [ ] 商店页文案、标签、截图、预告片完成
- [ ] 胶囊图符合当前尺寸与安全区
- [ ] 内容问卷与 AI 披露完成
- [ ] 价格与区域定价检查
- [ ] 发行日期/即将推出设置正确
- [ ] 发布负责人和最终点击时间明确
- [ ] 首发补丁、监控、社区公告就绪

上架流程本质上是项目管理：把它拆成可勾选的阶段，给每个阶段留出返工时间，比在上线前一周才发现素材尺寸不对要从容得多。
